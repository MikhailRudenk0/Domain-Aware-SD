# Отчёт: обучение 5 per-cluster драфтеров (WMT16 Translation)

**Дата**: 10-11 сентября 2026
**Общее время**: ~4.5 часа (последовательный запуск)

---

## Цель

Обучить 5 отдельных драфтеров — по одному на каждый из 5 WMT16 translation кластеров, которые показали наименьший Acceptance Rate на оригинальном графике. Проверить гипотезу: per-cluster специализация даёт прирост по сравнению с обучением на всех 11 Text Reformulation кластерах.

---

## Инцидент: OOM при параллельном запуске

При попытке запустить ruen + csen одновременно на 2 GPU, ruen был убит OOM killer (exit code 137). Причина: оба процесса одновременно загружали NPZ-данные в RAM и суммарно превысили 62 GB. Решение: перешли на последовательный запуск — по одному кластеру за раз.

## Наблюдения

1. **Переобучения не было** ни у одной модели. eval_loss монотонно снижался или оставался стабильным. Это значит, что 30K samples достаточно для 156M-параметровой модели с KD loss.

2. **Плато достигается к эпохе 5-6** у всех моделей. Оставшиеся 4-5 эпох дают микроскопические улучшения (<0.002 в loss). 5 эпох было бы достаточно.

3. **Разброс accuracy значительный**: от 49.36% (fien) до 54.91% (tren). Это отражает разную «предсказуемость» языков:
   - **tren (54.91%)** — турецкий agglutinative, больше морфологических паттернов → легче предсказать
   - **deen (52.77%)** — немецкий, относительно близок к английскому
   - **ruen (50.04%)** — русский, другой алфавит в оригинале, но SentencePiece нормализует
   - **csen (49.96%)** — чешский, похожая ситуация на русский
   - **fien (49.36%)** — финский, наиболее непредсказуемый из пяти

4. **Per-cluster vs multi-cluster trade-off**: tren per-cluster (54.91%) превосходит Text Reformulation 11-cluster (54.34%) по accuracy. Но остальные 4 кластера уступают. Это ожидаемо — per-cluster модель специализируется, но имеет меньше данных.

5. **RAM bottleneck**: параллельный запуск 2 моделей невозможен на 62 GB RAM из-за одновременной загрузки NPZ данных. Для будущих экспериментов: использовать memory-mapped файлы или lazy loading.

## История изменений метрик

### 2026-09-23: Фикс overlap_area + переход на model mode

**Проблема**: старый код (до 2026-09-23) вычислял `overlap_area` неправильно — вероятности драфтера ренормализовались на support таргета (top-10 таргета). Это искусственно завышало overlap_area (~3x для необученного драфтера).

**Фикс**: теперь overlap_area считается на объединении (union) top-K драфтера и top-K таргета. Каждая сторона использует свои собственные top-K вероятности, нули на позициях другой стороны. `overlap_area = sum(min(draft_raw, target_raw))`.

**Dataset mode deprecated**: eval всегда запускается с `target_source: model` (полный forward pass таргета). Dataset mode (`target_source: dataset`) систематически занижает метрики, т.к. видит только ~67% массы распределения таргета.

Все числа в секции "Evaluation results" ниже получены с исправленными метриками в model mode (2026-09-23).
